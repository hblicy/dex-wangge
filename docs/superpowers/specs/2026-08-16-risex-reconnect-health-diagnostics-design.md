# RISEx 重连健康状态与诊断修复设计

## 目标

修复 RISEx 手动重连已完成 REST/WS 对账并进入 `READY`，前端却因旧的只读刷新错误显示重连失败的问题；修复私有只读验证使用错误仓位接口的问题；保留网络错误的底层安全诊断信息。

## 行为设计

1. `_synchronizeLiveState` 只有在 Orders 快照、REST 快照、缓冲事件合并和订单归属校验全部成功后，才清除此前的 `_refreshError`。失败路径继续进入 `HALTED`，不清除错误。
2. 私有只读验证只调用一次 `/v1/positions` 对应的 `getAllPositions(account)`，严格校验数组和唯一 `market_id`，再按 BTC-PERP/ETH-PERP 分配仓位；不从请求参数推断缺失的市场 ID。
3. 记录网络错误时输出错误链中的 `name`、`code` 和 `message`，并标明失败阶段；不输出 URL 查询参数、账户、签名、私钥或响应正文。
4. 不为下单、撤单、杠杆或其他写请求添加自动重试；本次也不改变 RISEx 的 `HALTED` 安全边界。

## 数据流

- 手动/自动重连：私有 WS 认证 → Orders 快照 → REST 订单/成交/持仓/余额快照 → 归属校验 → 清除旧只读错误 → `READY` → 网格立即对账。
- 私有验证：公共市场信息 → 私有 WS 认证 → 全持仓读取 → 按市场映射 → 开放订单/成交读取 → 只读结果。
- 错误诊断：捕获外层错误 → 遍历 `cause` 链 → 生成脱敏摘要 → 终端日志与状态原因。

## 验证

- 先用失败测试证明成功重连后旧 `_refreshError` 仍阻止 `fetchOpenOrders`。
- 先用失败测试证明私有验证调用了单市场 `getPosition`。
- 先用失败测试证明嵌套网络错误目前只显示 `fetch failed`。
- 修复后运行 RISEx 相关测试和完整测试套件。
