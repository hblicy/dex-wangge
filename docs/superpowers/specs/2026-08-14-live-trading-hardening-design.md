# 实盘交易安全加固设计

## 目标

在不改变网格策略含义和仪表盘操作方式的前提下，修复已复现的实盘阻断问题，使订单撤销、区间风控、成交回报、重启恢复、持久化和密钥权限都遵循“无法确认就停止，不以成功状态继续”的原则。

## 范围

本次修改覆盖：

- `src/bot.js`：启动参数、杠杆设置、撤单、区间外动作、平仓确认和恢复状态机。
- `src/exchange/ex/extended.js`：nonce 合法范围、字符串订单标识和撤单标识。
- `src/exchange/de/decibel.js`：部分成交的真实成交数量。
- `src/exchange/rs/risex.js`、`src/exchange/rs/index.js`：禁用未达到生产可用标准的 RISEx 实盘适配器，保留 paper 模式。
- `src/server.js`：实盘初始化失败、恢复顺序、`.env` 权限和进程退出处理。
- `src/persist.js`：状态读写失败可观测、同步落盘和显式刷新。
- `README.md`、`.env.example`：同步部署和实盘限制。
- 新增针对交易生命周期、适配器和持久化的自动化测试。

不迁移 RISEx 到尚未稳定的官方接口，不修改网格计算模型，不增加新依赖，不调用真实交易所。

## 核心不变量

1. 交易所未明确确认“全部撤单成功”时，不得清空本地订单跟踪、重挂新区间或报告停止成功。
2. 启动价格位于配置区间外时，不得挂出任何订单。
3. 杠杆设置失败、参数非有限数或格数不是整数时，启动必须失败。
4. 平仓只有在指令成功且持仓查询确认归零后才能报告成功；无法确认时必须返回失败并保留可操作状态。
5. 成交替换单数量必须使用交易所确认的实际成交量。
6. 重启恢复必须先按持久化市场名称解析当前 marketId，再接管订单。
7. 实盘交易所初始化失败必须阻止服务进入可交易状态，不能伪装为真实数据源正常运行。
8. 状态和密钥文件写入失败必须被记录并向调用方传播；Linux `.env` 必须为 `0600`。
9. RISEx live 模式必须明确拒绝启动，paper 模式继续可用。

## 设计

### 交易状态机

为 `GridBot` 增加集中式输入校验和“要求撤单成功”的窄边界。`cancelAll` 只有返回明确成功值才允许后续状态切换；抛错、`false` 或无法确认都视为失败。`start`、`adjustRange`、`stop`、`cancelAllOrders`、`closePositionNow` 和遗留订单恢复统一使用该边界。

启动获取现价后先验证价格位于区间内，再注册事件并挂初始网格。区间调整只有撤单成功才替换配置和挂单。平仓失败时抛出错误，不将机器人标记成已安全停止。

### Extended

nonce 使用加密随机数生成 `1..2^31` 范围内的整数。订单跟踪始终以请求中的字符串 `externalId` 为主键，撤单也使用该字符串标识；API 返回的超大数字 `id` 不进入 JavaScript `Number` 标识链路。开放订单和历史对账优先使用 `externalId`，缺少字符串标识的记录不用于破坏性撤单。

### Decibel

订单历史给出 `orig_size - remaining_size` 时，将该值作为成交事件的 `sizeBase`。只有状态确认全部成交且计算值不可用时，才使用原始委托数量。取消或未知状态不产生成交事件。

### RISEx

由于已安装 SDK 明确声明未达到生产可用标准，`RS_MODE=live` 在配置/适配器创建阶段抛出清晰错误。paper 模式和页面展示继续保留。重新开放 live 必须作为独立项目，基于官方认证通道和 `filled_size` 完成测试网集成验证。

### 恢复与持久化

服务启动时，先读取快照并用 `displayName` 在当前市场列表中解析 marketId，再调用 `bot.resume`。对账必须被 `await`，失败会让恢复失败并保持明确错误状态。

持久化层不再吞掉 JSON 损坏、写入或重命名错误。保存操作保留原子临时文件替换，但提供同步 `flushState`，由 `SIGINT`/`SIGTERM` 退出路径调用。关键失败写入结构化 `console.error`，包含操作和文件路径，不包含密钥或快照正文。

### Linux 密钥权限

创建或重写 `.env` 时显式使用 `0600`，写完后在 POSIX 平台执行权限校验。实盘模式检测到 group/other 权限位时拒绝启动，并提示 `chmod 600 .env`。README 使用 dedicated service user、`umask 077` 和 `chmod 600 .env`。

## 错误语义和可观测性

- 关键交易动作失败时保留原始异常作为 `cause` 或错误消息的一部分，并记录交易所、市场和动作，不记录凭证。
- HTTP 端点沿用现有错误响应结构，但不能在底层失败后返回成功状态。
- 后台定时对账失败要节流记录，不允许空 `catch`。
- 非关键通知发送失败不改变交易结果，但需要保留现有告警记录。

## 测试设计

新增 Node 测试覆盖：

- 撤单返回 `false` 或抛错时，调整、停止和重挂均失败且本地跟踪不丢失。
- 区间外启动零挂单并失败。
- 非整数格数、`NaN` 数量/杠杆被拒绝。
- 平仓调用失败或持仓未归零时返回失败。
- Extended nonce 边界和字符串 externalId 撤单。
- Decibel 部分成交只发出实际成交数量。
- 恢复前按名称解析 marketId，并等待对账完成。
- 状态文件损坏和写失败不会被静默转换为空状态。
- Linux 权限辅助函数拒绝 `0644`、接受 `0600`，写入接口指定 `0600`。
- RISEx live 明确失败、paper 正常创建。

每个修复遵循红—绿测试循环；最后运行完整 `npm test`、全量 JavaScript 语法检查、`npm audit --omit=dev` 和不联网的假交易所回归脚本。

## 验收标准

- 上述核心不变量均有自动化测试。
- 原撤单失败复现不再出现“交易所 8 单、本地 4/0 单”的状态分裂。
- 现有 31 项测试保持通过。
- 不读取、输出或提交 `.env`。
- 不发生真实交易所请求。
- 文档明确 RISEx live 当前不可用及重新开放条件。
